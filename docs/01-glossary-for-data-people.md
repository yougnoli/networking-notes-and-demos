# A networking glossary for data people

Short, blunt translations. Each of these gets a full doc later — this is
just so nothing in the early reading stops you cold. No prior networking
knowledge assumed anywhere below.

| Term | In data/API terms |
|---|---|
| **IP address** | Like a primary key, but for a machine instead of a database row. It uniquely identifies a device (or one network interface on it) so data knows exactly where to go. |
| **Subnet** | Like a partition in a data warehouse table. Machines in the same subnet can talk to each other directly and cheaply; reaching a machine in a *different* subnet needs a router in between, the same way a query that crosses partitions costs more than one that stays inside a single partition. |
| **Subnet mask / CIDR (`/24`)** | The partitioning scheme itself: how much of the IP address is "which partition" versus "which specific machine inside it." |
| **Default gateway** | Where a device sends anything it doesn't know how to deliver itself — the same idea as a catch-all `ELSE` branch in a `CASE WHEN`, or a default route in an API gateway: "I don't have a specific rule for this, so send it here and let something smarter figure it out." |
| **DHCP** | An auto-assignment service for IP addresses, on a lease that expires. It's the same pattern as a temporary, auto-rotating access token or a surrogate key generated by a database: your laptop asks "give me an address," a DHCP server hands one out from a pool, and it's reclaimed if not renewed. |
| **NIC (Network Interface Card)** | A physical or virtual network "port" a device uses to connect to a network. **Multihomed** just means "has more than one" — a laptop with Wi-Fi, Ethernet, and a VPN connection all active at once has three. |
| **NAT (Network Address Translation)** | Similar to how a connection pool multiplexes many application-level connections onto a handful of actual database connections: many internal, private addresses get rewritten to look like one shared public address as they leave a network, and something remembers the mapping so replies find their way back to the right one. |
| **Firewall** | An access-control layer for network traffic, evaluated per-packet instead of per-query — conceptually the same as row-level or column-level access grants on a data warehouse table. The default posture is usually "deny everything, then explicitly allow only what's needed," the same least-privilege instinct behind giving a service account access to only the specific tables it needs. |
| **VPN (Virtual Private Network)** | An encrypted tunnel that makes a remote device act as if it's plugged directly into a private network. Similar in spirit to a private, IP-restricted connection to a data warehouse (like a Snowflake private link or a database that only accepts connections from a specific network) — except a VPN does this for *all* of a device's traffic, not just one connection. |
| **Load balancer** | The same thing as spreading requests across several replicas of an API or a model-serving endpoint so no single instance gets overwhelmed — if you've ever seen "N replicas" or "autoscaling" behind an API, something upstream of it was almost certainly doing this. |
| **WAF (Web Application Firewall)** | Input validation, but centralized and running as network infrastructure instead of application code. It reads the actual content of a request — the URL, headers, body — and blocks ones that look like an attack (SQL injection, script injection), the same instinct as sanitizing user input before it reaches a database, or filtering a prompt before it reaches a language model. |
| **Reverse proxy** | A layer that sits in front of your "real" servers and forwards requests to them on the client's behalf, while doing bookkeeping along the way (adding headers, rewriting paths, sometimes caching) — the same role an API gateway plays in front of several backend services. |
| **TLS termination** | The point where encrypted ("HTTPS") traffic gets decrypted back into plain, readable data. Everything *after* that point can see the actual content; everything *before* it only sees unreadable encrypted bytes. Every HTTPS API call you've made from Python or a notebook was encrypted right up until it hit this point somewhere on the provider's infrastructure. |
| **Port** | A sub-address on a machine — the IP address gets your data to the right machine, the port gets it to the right process running on that machine, the same way a table name narrows down which table inside a whole database you mean. |
| **Packet** | One unit of data traveling on the network — like one row or one message in a queue: it has a small header (metadata: where it's from, where it's going, what kind of traffic it is) and a payload (the actual content). |
